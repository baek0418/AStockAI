# AStockAI

**把 A 股行情、策略研究、持仓与每日复盘，放进一个本地工作台。**

AStockAI 是一个基于 Python 与 Streamlit 的开源 A 股研究工具：从下载行情、核对证据，到查看个股、整理持仓和生成日报，把日常研究流程串起来。无需 AI API Key 即可开始使用；需要时再接入自己的大模型服务，辅助解读研究材料。

[快速开始](#第一次使用照着做即可) · [功能介绍](#你可以用它做什么) · [数据与回测边界](docs/research_backtest_contract.md) · [问题反馈](https://github.com/baek0418/AStockAI/issues)

## 你可以用它做什么

| 你想做的事 | AStockAI 提供的支持 |
|---|---|
| 每天更快进入复盘状态 | 行情更新、量化快照、日报与系统状态集中查看 |
| 研究一只 A 股 | 按代码或名称查找，按需下载日线，查看技术指标与研究证据 |
| 按不同思路核对机会 | 策略筛选、周期分类，以及 30 位投资大师公开理念的研究清单 |
| 管理自己的观察与持仓 | 本地关注列表、手动持仓管理、独立模拟仓与交易流水 |
| 检查研究结论是否可靠 | 来源记录、数据日期校验、样本外研究与历史输入审计 |

## 为什么做这个项目

投资研究常常分散在行情软件、表格和笔记里。AStockAI 希望把这些步骤连接起来，让每次复盘都能回答：**数据来自哪里、更新到哪天、结论依据是什么、还有哪些证据缺失。**

- **先有数据，再做解读**：核心流程可独立于 AI 运行，AI 分析按需启用。
- **研究过程可以追溯**：行情记录来源和复权方式；下载失败保留旧文件，明确显示问题。
- **回测有明确的输入门槛**：核对历史成分、原始成交价格、交易状态和公司行为；证据不足时输出拒绝原因。
- **个人工作台留在本机**：持仓、关注列表和研究产物默认在本地保存，不连接券商，也不自动交易。手动启用 AI 或邮件时，相关请求内容会发送到你配置的服务。

Local A-share research workspace with traceable market data, portfolio tracking, daily reports, and optional AI analysis.

> 仅供研究与学习，不构成投资建议、收益承诺或目标价。

## 第一次使用：照着做即可

需要 Python 3.10 或更高版本，以及能访问公开行情服务的网络。

```bash
git clone https://github.com/baek0418/AStockAI.git
cd AStockAI
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python setup_local.py
.venv/bin/streamlit run app.py
```

浏览器打开终端显示的本机地址（通常是 `http://127.0.0.1:8501`）。首次初始化会创建你的本地空关注列表，并下载股票池的日线、生成量化快照和日报；通常需要数分钟。它**不会**调用 AI、发送邮件或读取券商账户。

如果初始化中断，网络恢复后再次执行下面这条命令即可；已有的本地数据不会被清空：

```bash
.venv/bin/python setup_local.py
```

## 项目目录

根目录只保留直接使用的入口：

- `app.py`：启动网页。
- `setup_local.py`：首次初始化本地数据。
- `pipeline.py`：手动执行完整的数据、研究和日报流程。
- `background_task_runner.py`：网页后台任务入口，无需手动运行。

业务代码集中在 `astock_core/`，按职责分为 `analysis/`（分析）、`data/`（行情与股票池）、`portfolio/`（持仓）、`simulator/`（模拟仓）、`strategies/`（策略执行）、`reporting/`（日报）、`research/`（研究）和 `runtime/`（后台任务与日志）。`tests/` 用于开发验证，`config/` 存放公开配置；数据、模型、日报和持仓默认保存在本机，不随代码提交到 GitHub。

### 为什么刚下载时页面内容较少？

这是刻意的隐私设计。GitHub 不包含任何人的行情快照、日报、模型、持仓、关注列表或邮箱配置。下载项目后，先运行 `setup_local.py` 才会在**你自己的电脑**生成这些内容。持仓管理中的账户、成本和数量也只保存在 `data/portfolio.json`，不会上传 GitHub。

## 日常使用

- **投资总览**：先看持仓数据是否齐全，以及当天要核对什么。
- **持仓管理**：手动录入、预览并确认保存本地持仓；没有券商连接，不是实时盘中行情。
- **策略中心**：选择并手动运行策略。首个“A股午后强势筛选”会在交易日 14:30 后核验公开实时行情、日线和分时证据，保存带时间戳的结果；数据不足或无完全符合条件的股票时会明确说明。
- **策略周期与研究框架**：策略卡会标注短线、中长线或长线。用户可按周期筛选，并将内置框架或“30 位投资大师公开理念参考”设为单股研究框架；每项均记录第三方 skill 来源，但只使用公开方法论主题，不加载角色扮演规则。周期表示本项目的研究复核频率，不是作者承诺的持有期。这些框架只改变证据核对清单，不是任何个人或金融机构的官方观点或自动交易策略。
- **模拟仓**：独立于真实持仓的本地模拟现金、持仓和流水。用户确认后可按策略快照价格建立模拟仓，不能向券商发送任何指令，也不把快照价描述为下一交易日实际成交价。
- **单股票查询**：输入股票代码或名称。已生成本地快照的股票可直接查看；其他股票需要你点击“下载并分析”。
- **未来 5 日风险范围**：只在单股票页、原始日线和研究验证都齐全时显示。它表示按最近波动估算的常见价格范围，不是目标价或买卖建议。
- **系统状态**：只有出现数据问题或你想手动刷新时再查看。

页面只绑定本机 `127.0.0.1`，不会部署到公网。数据写入后刷新浏览器即可看到最新内容。

## 可选：AI 与邮件

默认不需要配置 `.env`。如果你希望手动使用 AI 分析或发送日报邮件，再复制并填写模板：

```bash
cp .env.example .env
```

`.env`、邮件地址、授权码和 API Key 都不会被提交。即使不配置，它也能正常使用本地数据、规则分析与网页查询。

## 可选：测试与高级研究

运行测试（不会下载行情、调用 AI 或发送邮件）：

```bash
.venv/bin/python -m unittest discover -s tests -v
```

收益区间的研究口径与边界见 [说明文档](docs/return_interval_research.md)。历史股票池、原始成交价格、公司行为和交易状态的严格回放契约见 [研究与回测数据契约](docs/research_backtest_contract.md)。输入证据不完整时研究入口会生成拒绝记录，不再输出未经核验的策略收益。

## 任意 A 股按需查询

“单股票查询”会先复用已有 `quant_snapshot` 中的股票，避免重复下载。对于其他 A 股：

1. 输入六位代码，或先点击“更新本地代码目录（可选）”后按名称、模糊名称查找；目录只保存代码与名称。更新优先使用上交所、深交所公开 HTTPS 股票列表，无需配置 BaoStock 直连；仅在该来源临时不可用时自动尝试 BaoStock 兜底。
2. 选择候选股票后，点击“下载并分析”才会请求这一只股票的历史日线。
3. 临时日线与分析快照分别保存在 `data/on_demand/`、`output/on_demand/`，不参与日报、研究股票池或回测。
4. 页面会标注最近日线数据日期；它不是实时盘中行情。AI 分析仍须手动点击触发。
5. “加入关注列表”是唯一会修改 `watchlist.json` 的显式操作，新增股票将在下一次股票池更新时生效。

六位代码直查不依赖名称目录：点击下载后会由腾讯接口识别股票并获取日线。名称和模糊名称仅使用已有本地目录；目录刷新失败（包括代理错误）时，页面会提示可继续输入六位股票代码。按需快照会记录行情来源与名称目录来源；不会修改用户代理配置或尝试绕过代理。

## 基本面与研究功能

单股票页可查看已有本地基本面事实快照，包括来源、报告期和可核对指标。**基本面在线下载与研究池自动刷新暂时停用**，等待替代数据源验证，界面会明确提示。系统状态中的高级信息保留了数据审计与样本外研究，供需要时展开查看。收益区间的口径、验证方式与边界见 [说明文档](docs/return_interval_research.md)。

## 数据生产与故障检查

手动刷新行情、基准、研究快照和日报（不调用 AI、不发送邮件）：

```bash
.venv/bin/python pipeline.py --no-ai
```

正式股票和指数日线仅保存最近已结束交易日的数据。北京时间 15:30 前按上一交易日校验，周末与休市日按 `config/a_share_market_holidays.json` 回溯；未配置年份会明确报错。接口返回的盘中当日日线不会写入正式日线。响应日期落后时保留原文件并记录失败，需进一步核对停牌或数据源延迟，不能当作更新成功。

正式日线优先使用腾讯前复权，失败后尝试 BaoStock 0.9.3 前复权；两者均失败则保留旧文件，不回退到未复权数据。东方财富所有联网入口已移除。原始价格研究仍使用隔离目录。更新采用限速与有限重试；指数请求也会重试暂时性错误。检查 `output/pipeline_status.json` 中个股失败明细、最新行情日期和基准结果，具体请求错误见 `logs/market_data_update_<日期>.jsonl`。部分失败时即使日报生成成功，流水线也不会显示全部成功。来源留痕的更新时间表示下载时间，日期范围表示行情覆盖日期，两者含义不同。

离线复核所有正式股票及两个基准的日期、来源和未复权数量：`.venv/bin/python -m astock_core.data.production_audit`。结果写入 `output/data_production_status.json`。正式股票写入入口会拒绝非 `qfq` 结果；审计发现历史遗留的未复权记录或日期落后时，标记为部分完成。

数据源限制：禁止使用东方财富接口（包括备用源）。基本面下载和研究池自动刷新暂时停用，待替代来源验证后恢复；已有本地文件及其真实来源记录保留，不能据此声称完成新下载。


BaoStock 备用源逐行检查股票代码与 `adjustflag=2`，成交量由股统一换算为手。每次查询在独立进程中执行，25 秒超时即停止，避免旧客户端或服务故障挂住整个批次。已有未复权误覆盖文件可运行 `.venv/bin/python -m scripts.recover_qfq` 恢复；工具仅处理来源标记为 `raw` 的正式股票，先在 `output/recovery/` 下载、核验并备份，再替换完整历史和来源记录。恢复后需重新生成快照和日报。
